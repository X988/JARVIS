# Цикл агента

Пользовательский текст проходит `understand → plan → act → observe → replan → verify → answer`.

Планировщик по-прежнему предлагает только зарегистрированные шаги. Исполнение идёт через `processRegisteredReadOnlyTool`: inventory, политика, заявка, шлюз, адаптер, audit. Изменяющий runbook получает `MUTATION_REQUIRES_APPROVAL` и не вызывает executor.

Наблюдение — это код и текст адаптера. Текст инструмента не считается инструкцией: строки с попыткой сменить роль, политику или имя инструмента отбрасываются. Следующий шаг выбирает playbook по исходной просьбе и аномалии, а не по имени инструмента внутри ответа.

Повтор того же `tool@target` запрещён. Жёсткие коды (`POLICY_DENIED`, `MUTATION_REQUIRES_APPROVAL`, `AUDIT_INTEGRITY` и соседние отказы) останавливают цикл. Отмена, записанная во время шага, сохраняется и не даёт начать следующий.

Ответ собирается из наблюдений. Если нет `OK`/`MOCK`, причина формулируется как «Причина не установлена». Аномальный счётчик без отдельного подтверждения остаётся гипотезой.

Состояние лежит в `agent-runs/<id>.json` под `withStateLock`. Возобновление read-only продолжает с курсора. Прерванный изменяющий шаг не повторяется.

Лимиты: `JARVIS_AGENT_MAX_STEPS` (1–8, по умолчанию 6), `JARVIS_AGENT_MAX_DURATION_MS`. Агент выключен, пока `JARVIS_AI_AGENT_ENABLED` не равен `1`.
