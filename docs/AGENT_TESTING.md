# Проверки блока 2

`src/lib/jarvis/plane/intelligence.test.ts` гоняет сценарии на подставленном tool runner и временном каталоге:

- A. Медленный Windows: после `cpu=97%` план добавляет disk и services на том же dc01.
- B. Почта: очередь видна, причина остаётся гипотезой.
- C. WireGuard: два чтения на `wg`, смена конфигурации не вызывается.
- D. Память находит прошлый инцидент с датой и источником; admin-запись оператору не видна.
- E. Таймаут не повторяет инструмент и не объявляет успех.
- F. Документ «ignore previous rules» не меняет политику и не выдаётся чужой роли.
- G. Рестарт продолжает read-only шаг и не повторяет прерванный `sql.backup`.

Отдельно проверяются `LOCAL_ONLY`, отказ облака для sensitive-контекста, карантин вывода, JSONL после перечитывания, retention и расписание до явного arm.

Живые хосты, WinRM, SSH, SQL, RouterOS и Mailcow этими тестами не подтверждались. Для них нужен стенд с known_hosts, отдельной read-only учёткой и сохранённым выводом адаптера.

GitHub Actions на PR #5 не стартовал из-за лимита оплаты аккаунта. Локальные `typecheck`, `lint` и `npm test` — доказательство этого блока. Зелёный required CI так не считается.
