## Подтверждённые проблемы и исправления

### P0 — подмена оператора и обход Gateway

`tools/api.ts` экспортировал server functions без проверки JARVIS-сессии/CSRF.
`runtime.server.ts` выбирал actor по `operatorId` из браузера; при отсутствии
конфигурации использовал `DEMO_ACTORS`, включая admin1. `store.ts` вызывал этот
контур раньше основного session pipeline. В `live` режиме он мог запускать SSH
и RouterOS без основного Inventory/Policy/Approval Gateway.

Исправление: web API больше не экспортирует legacy запуск/подтверждения и не
создаёт ToolEngine. Из текстовой консоли удалены demo-выбор роли и прямой tool loop.
Текст идёт в `/api/agent`, подтверждения — в `/api/commands`. Сессия, CSRF, origin,
rate limit, политика и реальный режим выводятся на сервере. Существующий voice
контур сохранён. Для неизвестного текста доступен уже реализованный hybrid AI.

Legacy engine остаётся в исходниках для изолированных тестов. Это не разрешение
вновь подключать его к HTTP: сначала нужна интеграция с единым Gateway.
Добавлен регрессионный тест отсутствия legacy импортов в web runtime.

### P0 — несовместимые записи в одном audit.jsonl

Legacy engine писал обычный JSONL по умолчанию в `data/audit.jsonl`. Основной
контур использует тот же путь для hash chain. Строка второго формата нарушает
целостность цепочки; обычный pipeline после этого отказывает в исполнении.

Исправление: legacy writer отключён от web; `/admin/audit` читает основной журнал
под state lock, проверяет hash chain и требует серверную роль admin. Устаревшие
строки не получают выдуманную роль. Уже повреждённые данные не удаляются и не
«перехешируются»: требуется отдельное расследование и восстановление.

### P1 — просроченная сессия могла попасть к модели

`runAgentTurn` проверял роль, но не `expiresAt` перед вызовом planner. Внешний HTTP
контур перепроверял пользователя, однако сама функция не соблюдала свой session
контракт и могла использоваться другими вызовами.

Исправление: срок сессии проверяется до planner. Тест подтверждает отсутствие
LLM/tool вызовов для просроченной сессии. Тест с фиксированным временем теперь
явно передаёт это время в runtime.

### P1 — успешная сборка падала при запуске PGlite

В собранном Nitro/Vercel пакете отсутствовали `pglite.data`, `pglite.wasm` и
`initdb.wasm`. При старте preview сервер завершался с ENOENT. Это воспроизведено,
а не выведено из предположений.

Исправление: build копирует runtime assets рядом с PGlite bundle. При изменении
структуры bundle упаковка явно завершается ошибкой. Добавлены тесты упаковки и
проверен реальный запуск собранного приложения после исправления.

### P1 — зависимости и ложный secret-scan alarm

`npm audit` нашёл две moderate уязвимости в цепочке SQL Server adapter.
Совместимое обновление подняло tedious до 20.3.7; повторный аудит: 0 уязвимостей.
SBOM дополнительно обнаружил несовместимый optional peer: unstorage требовал
lru-cache ^11.2.6, но дерево подставляло Babel-зависимость 5.1.1. Явная совместимая
версия lru-cache устранила конфликт; CycloneDX SBOM успешно сформирован.
Тест security-core содержал literal, похожий на настоящий API key. Тестовое
значение теперь строится во время выполнения; проверка redaction сохранена.

### Поддерживаемость и запуск

- Удалены tracked `.vercel/output` артефакты: они могли продолжать содержать
  старый небезопасный код после исправления исходников. Сборка создаёт их заново.
- Согласован execution mode: gateway использует `mock | dry-run | real`;
  `live` не включает отдельный сервис. Обновлены `.env.example` и документация.
- `startup.sh` работает из каталога checkout, а не из жёсткого `/workspace`.
- Текстовая консоль показывает коды ошибок AI даже без command trace.
- Исправлен устаревший каталог клонирования в README.

## Выполненная проверка

Среда: Linux, Node 24.19.0. CI проекта настроен на Node 22; локальная проверка
именно на Node 22 в этом проходе не проводилась.

- TypeScript: pass.
- ESLint: 0 errors; 2 существующих Fast Refresh warnings в voice-call.tsx.
- `npm test`: 492 tests (212 JS/script + 280 TypeScript), все pass.
- Coverage: lines 81.15%, branches 68.27%, functions 78.54% для набора coverage.
- Playwright: 4/4 pass — запрос через `/api/agent` без operatorId, отказ неизвестному
  actor, DENY_ALWAYS и доступ к журналу по серверной роли.
- Secret scan: pass для отслеживаемых исходников.
- npm audit: 0 vulnerabilities после обновления.
- Build + упаковка PGlite: pass; собранный сервер и `/login` запускаются.
- Desktop/mobile smoke: страницы непустые, нет horizontal overflow и page errors;
  built/dev snapshots не расходятся. В анонимном smoke ожидаемый 401 от session API
  и ошибки загрузки внешних Grok assets в этой среде. Это не чистый console pass;
  реальные авторизованные LAN-сессии и доступность внешних assets требуют проверки.

Последние GitHub Actions интеграционной/security веток имели failure без доступных
шагов/логов. Причина не подтверждена. Успешные локальные проверки не означают зелёный
GitHub CI и не обходят обязательные branch checks.

## Что остаётся до эксплуатации

1. На тестовом LAN подтвердить HTTPS-вход, persistence PGlite/PostgreSQL, привязку
   реальных пользователей, logout и отсутствие test-auth в production.
2. Подтвердить fixed SSH probes с заранее установленным known_hosts, RouterOS TLS,
   SQL backup + VERIFYONLY и отдельный реальный restore. Никаких live изменений
   инфраструктуры в этом проходе не выполнялось.
3. Проверить Telegram webhook/replay и реальные STT/TTS процессы, затем согласовать
   права текстового и голосового каналов.
4. Провести восстановление полного control-plane state и внешнего audit sink.
   Hash chain обнаруживает изменение строк, но без внешнего anchor не доказывает
   отсутствие замены всего файла.
5. Спроектировать ротацию/архивирование аудита. Текущий append/verify читает всю
   цепочку; admin view отказывается читать файл больше 8 MiB. Это ограничение
   масштабирования, а не механизм автоматического удаления истории.
6. Legacy tool UI возможности переносить через зарегистрированные runbooks и
   Gateway. Нельзя возвращать отдельные approvals в памяти, accept-new SSH или
   отключение TLS. Реальное изменение интерфейсов MikroTik требует rollback и
   отдельного безопасного сценария, включая риск потери управления.
7. Исправить эвристический static security scanner: он принимает RegExp.exec за
   child_process.exec в нескольких файлах. Его вывод сейчас нельзя считать
   доказательством shell vulnerability или надёжной AST-проверкой.

Проект остаётся pre-production. Наличие модулей memory/scheduler/MCP/voice само по
себе не доказывает автономную работу всей системы на целевой инфраструктуре.
