# Маршрутизация моделей

Назначение ложится на уже существующие jobs:

| Назначение | Job | Ожидание |
| --- | --- | --- |
| диалог, классификация | intent | быстрый локальный маршрут, если так настроен |
| планирование, длинные логи | research | более сильный разрешённый маршрут |
| код | coding | coding-провайдер |
| отчёт | sensitive | локально, облако только с явным разрешением |

Провайдеры те же: Ollama, OpenAI, Anthropic, Gemini. Имена моделей задаются `JARVIS_<PROVIDER>_MODEL` и job-переменными. `JARVIS_LLM_FAILOVER` перечисляет запасные провайдеры. Ошибка таймаута или upstream переходит к следующему. `LOCAL_ONLY` выбрасывает нелокальные попытки и отвечает `LOCAL_ONLY`, если Ollama не настроена. Молчаливого перехода в облако нет.

`probeOllama` вызывается отдельно и не выполняется на каждом запросе.

Инфраструктурный job `sensitive` не уходит в облако без `JARVIS_LLM_CLOUD_INFRA=1`. Секреты вырезаются `sanitizeLlmText` до отправки. Учёт хранит провайдера, модель, job, длительность и оценку токенов, без текста промпта. Одновременные вызовы ограничены `JARVIS_LLM_MAX_CONCURRENT`.
