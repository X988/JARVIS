# Единый путь исполнения JARVIS

Браузер отправляет текст в `POST /api/agent`, подтверждения — в `POST /api/commands`.
Оба маршрута проверяют серверную сессию, CSRF, origin и rate limit. Известные команды
обрабатываются детерминированным pipeline; свободные запросы — bounded AI agent.
Модель не получает произвольный shell и не может выдать себе approval.

`EXECUTION_MODE=dry-run` — значение по умолчанию. Для реальных адаптеров используется
только `real`. Старое значение `live` не включает сетевое исполнение.

## Совместимость

Ранее ветка tool-execution добавляла второй ToolEngine, demo-операторов, process-local
approvals и отдельный JSONL-формат. Он обходил основной Gateway и мог писать в тот же
`data/audit.jsonl`, повреждая hash chain. Этот engine больше не импортируется web API.
Старые server functions запуска и подтверждения не экспортируются. Исходники legacy
engine остаются для изучения и изолированных тестов; не подключайте их к внешним маршрутам.

Настройки `JARVIS_OPERATORS`, `JARVIS_MT_*`, `OLLAMA_*` и JSON secrets старого engine
не являются настройками действующего Gateway. Используйте `JARVIS_WEB_ACTORS_JSON`,
`JARVIS_OLLAMA_*`, `JARVIS_SSH_*` и `JARVIS_MIKROTIK_*` из `.env.example`.

## Журнал

`/admin/audit` читает последние 200 строк единой проверенной цепочки. Доступ определяется
серверной сессией роли `admin`; `operatorId` браузера не используется. Повреждённый журнал
не показывается как корректный. Для файла более 8 MiB просмотр требует архивирования;
это ограничение интерфейса, не автоматическое удаление или восстановление журнала.
Старые строки не содержат роль/режим, поэтому интерфейс не выдумывает эти значения.

Если старый engine уже дописал строки без hash chain, новая версия не исправляет и не
удаляет их автоматически. Сохраните оригинал, выясните происхождение повреждения и
проведите отдельную процедуру восстановления аудита перед включением реального исполнения.

## Проверки

`npm test` проверяет отсутствие импортов legacy engine из web runtime, защищённый
просмотр аудита, отказ по просроченной сессии и основной policy/approval pipeline.

## Навыки 1С

Тексты [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) (MIT, закреплённый commit в `vendor/cc-1c-skills/UPSTREAM.json`) попадают в ответ агента как фрагменты документации. Скрипты конфигуратора, PowerShell, Python, хуки и Playwright в реестр runbook не добавляются и shell не получают. Подробности и список исключений: `docs/ONEC_SKILLS.md`.
Live SSH, RouterOS, SQL backup и восстановление требуют отдельных проверок на тестовой
инфраструктуре. Сборка не заменяет эти испытания.
